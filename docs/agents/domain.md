# Domain documentation

Before exploring an area of the codebase, read the root [CONTEXT.md](../../CONTEXT.md) and the relevant decisions in [docs/adr](../adr/). This repository uses one domain context.

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. If a needed concept is missing, check whether an existing term covers it. Use the `domain-modeling` skill to resolve a new term and add it to the glossary.

When a proposal contradicts an ADR, identify the decision and explain why it needs to change.
